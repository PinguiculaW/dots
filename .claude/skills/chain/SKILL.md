# Запустить полный конвейер analyze → plan → do

Цель: последовательно выполнить три этапа для задачи, используя отдельный агент на каждый этап с изолированным контекстом.

## Аргументы

- `$ARGUMENTS` — номер задачи (обязательный). Формат: число, например `007`.

Если номер не передан — сообщить пользователю и остановиться. Не угадывать.

## Подготовка

Перед запуском найти папку задачи:
- Искать в `ai-process/tasks/{номер}-*/` и `ai-process/tasks-done/{номер}-*/`
- Запомнить полный путь к папке — он нужен для проверок и записи ошибок
- Если папка не найдена — записать ошибку (см. раздел «Обработка ошибки») и остановиться

## Шаг 1: analyze

Скил `analyze` перед работой проверяет `description.md` (раздел «Открытые вопросы»). Подробности — в скиле `analyze`.

Запустить агент:
```
Agent(
  subagent_type: "general-purpose",
  prompt: "Запусти скил analyze для задачи номер {номер}. Вызови инструмент Skill с параметром skill='analyze' и args='{номер}'. Дождись завершения и верни краткий итог: успешно или нет, и если нет — описание ошибки."
)
```

После завершения агента:
- Проверить наличие файла `analyze.md` в папке задачи
- Если файл **не** существует:
  - Прочитать `description.md` и применить те же правила, что в скиле `analyze`, для раздела «Открытые вопросы»
  - Если анализ **заблокирован** открытыми вопросами (содержимое раздела не пустое и не сводится к «нет вопросов» по правилам скила `analyze`) → **не** создавать `error.md`; сообщить пользователю, что нужно обсудить вопросы, обновить `description.md` и снова запустить `chain`; остановиться
  - Иначе → **обработка ошибки** (шаг: analyze)

## Шаг 2: plan

Запустить агент:
```
Agent(
  subagent_type: "general-purpose",
  prompt: "Запусти скил plan для задачи номер {номер}. Вызови инструмент Skill с параметром skill='plan' и args='{номер}'. Дождись завершения и верни краткий итог: успешно или нет, и если нет — описание ошибки."
)
```

После завершения агента:
- Проверить наличие файла `plan.md` в папке задачи
- Если файл не существует → **обработка ошибки** (шаг: plan)

## Шаг 3: do

Запустить агент:
```
Agent(
  subagent_type: "general-purpose",
  prompt: "Запусти скил do для задачи номер {номер}. Вызови инструмент Skill с параметром skill='do' и args='{номер}'. Дождись завершения и верни краткий итог: успешно или нет, и если нет — описание ошибки."
)
```

После завершения агента:
- Если агент сообщил об ошибках сборки, линтера или тестов → **обработка ошибки** (шаг: do)

## Обработка ошибки

При сбое на любом шаге:

1. Создать файл `{путь к папке задачи}/error.md`:

```markdown
# Ошибка выполнения цепочки

**Шаг:** {analyze | plan | do}
**Дата:** {текущая дата}

## Описание ошибки

{Подробное описание что пошло не так — из ответа агента или из контекста}

## Статус шагов

- {✅ | ⏭} analyze
- {✅ | ⏭} plan
- {✅ | ⏭} do

(✅ — выполнен, ⏭ — не выполнялся)
```

2. Сообщить пользователю: на каком шаге упало, краткая причина, путь к `error.md`.
3. Остановиться. Следующие шаги не запускать.

## Уточнения

- Номер задачи обязателен — без него не запускать
- Шаги выполняются строго последовательно: analyze → plan → do
- Каждый шаг — отдельный агент с изолированным контекстом
- Контекст между шагами передаётся через файлы на диске (analyze.md → plan.md → код)
- chain сам ничего не реализует — только оркестрирует
